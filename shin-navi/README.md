# 新ナビ コンセプト試作「MIRRORBALL（ミラーボール）」

カラオケルームの室内ナビとスマホを1つの入口にまとめた、**動くコンセプト試作**です。
部屋の空気を読んだ“光の札”をめくって、投げて、貼る。歌うたびに、あなたのミラーボールに光の面が1枚ずつ増えていきます。

> 試作のため、楽曲の認知度・声域・空気感タグなどはすべて**デモ用の推定値**です。
> 歌詞は表示せず、実在の音源も再生しません（効果音とメロディはブラウザ内で合成しています）。
> OTA予約・モバイルオーダー・サブスク連携・ログインは**模擬**で、外部サービスにはつながりません。

## 開き方

- ビルド済みの `dist/index.html` は外部ファイルに依存しない1枚のHTMLです。スマホでもPCのブラウザでもそのまま開けます。
- 開発サーバー：`npm install` → `npm run dev`
- ビルド：`npm run build`（`dist/index.html` が1つ出力されます）

### URLパラメータ

| パラメータ | 効果 |
|---|---|
| `?view=dual` | 発表用の2画面（左：スマホ、右：部屋のタブレット） |
| `?view=room` | 部屋のタブレット表示 |
| `?script=1` | 台本モード（大きな出来事は「→」キーか発表者パネルの「次へ」でだけ進む） |
| `?seed=demo` | 同じ夜を再現する乱数の種 |
| `?locale=en` など | 初期の言語（`ja` `en` `zhHant` `zhHans` `ko`） |
| `?seedNights=2` | 過去の夜をデモ用データとして読み込む（画面に「デモ用データ」と表示） |
| `?reset=1` | 保存データを消して最初から |
| `?entry=1` | 入口画面（言語選択・旅のしおり）から始める |

### 発表者の操作

- ブランド表記「新ナビ（コンセプト試作）」を3回タップ、または `?` キーで**発表者パネル**
- `L` キーで**企画レンズ**（各画面がどの施策・検証指標に効くかを重ねて表示）
- `S` キーで**比較スプリット**（申告式の固定リスト vs 部屋を読む新ナビ）
- `→` キーで台本の次の出来事

## 3分デモ（推奨：1366×768 のPCで `?view=dual&script=1&seed=demo`）

1. **何も触らずに3秒**：ボールが降り、光が散り、床に同室者が灯り、最初の札がせり上がる。
2. **画面をタップ → 口火の札を上に投げる**：部屋の明かりがつき、札が予約列に飛び込み、ボールの面がネオンに灯る。
3. **つながる札・知ってる？**：ボールの面と面が光の線で結ばれ、「知ってる」のドットが1つずつ灯る（答えた人の分だけ数える）。
4. **右に払う・持ち込みを保存**：触ったものが全部、自分のボールの面として残る。
5. **比較ON → ジュン合流**：固定リストは変わらず、新ナビだけが配り直され「ジュンが合流したので」と越境の札が出る。
6. **空気の変わり目 → 次に挟む**：しっとりが続いた流れを変える一手。
7. **あなたの番 → 歌い終わった → 3つの質問**：「今回の声は…」と、キー付きで予約できる1曲。
8. **乾杯コースター**：同じ入口から注文。二重注文を防ぎ、退室したら締まる。
9. **한국어 → 「잔혹한」で検索**：現地の文字でもローマ字でも目的の曲に着く。
10. **退室 → 今夜のまとめ → スタンプ**：今夜の面・声・共通曲・光座の名前・今夜のメロディ。最後の8秒だけ `L` で施策を重ねる。

## 「ナビ進化：重要施策」との対応

| 施策 | この試作での形 |
|---|---|
| 5-1 インバウンド | 5言語の即時切替、原題・ローマ字・現地文字のどれでも検索、言語ごとの最初の3枚の出し分け、越境の札、「予約済み #n」と演奏順、入口の旅のしおり（OTA導線の模擬） |
| 5-2 探し方 | 根拠タグ（実線）と仮説タグ（点線「ナビの見立て」）の分離、空気ミキサー（設問の代わりの2軸パッド）、「一緒に選ばれている」をタグ推薦と別枠で表示、知ってる？、未踏の面から絞り込み検索、空気の変わり目 |
| 5-3 連携 | サブスクのお気に入りを本人のスマホにだけ“候補”として表示 → 版を選んで明示的にマイうたへ保存 → 次回来店の最初の手札 |
| 5-4 アプリ整理 | 探す／歌う／記録／注文の4入口、QR参加・ログイン不要、採点と声の分析を1枚に統合（今夜の声）、モバイルオーダー（重複防止・退室後ロック） |

勝ち筋「誰・繋・読・訪・連」は、床の光と合流時の読み直し（誰）、光の線と共起（繋）、オーロラと気分語・原因まで書いた理由の1行（読）、越境の札と5言語（訪）、持ち込みとマイうた（連）として動いています。利用者の画面には社内の用語を出さず、企画レンズでだけ表示します。

## 設計の約束

- **中毒性＝自発的に続けたくなる楽しさ。** ガチャ・課金・連続日数・偽の希少性・カウントダウン・注文への報酬・止めにくい無限フィードは使いません。7枚ごとに「ひと息」を入れ、いちばん大きいボタンは「スマホを置いて聴く」です。
- **プライバシーの境界。** 部屋の共有画面には個人のサブスク曲・履歴・声を常時表示しません。「知らない」と「未回答」は同じ見た目で、誰が知らないかは分かりません。同室者の歌唱は本人の記録に混ざりません。
- **性能。** 描画ループは1本、アニメーションは transform と opacity だけ、Canvas は事前に描いたスプライトを使い、端末に合わせて品質を自動で下げます。

## 開発

- 構成：`src/core`（型・ストア・ルール・基盤）、`src/app`（画面の組み立て）、`src/features/*`（機能モジュール）、`src/data`（楽曲シード）、`src/i18n`（5言語の辞書）
