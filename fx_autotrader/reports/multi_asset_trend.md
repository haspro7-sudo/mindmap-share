## 結論

**判定: no_edge（本番採用しない）**

問い: FXだけのトレンドフォローは2005年以降に効かなくなった（第1波）。株価指数と金を加えれば、2005-2020年と先物2020-2024・FRED 2020-2026のチェックで頑健なエッジが戻るか。

答え: **戻りません。**

* ISで選んだ設定は IS Sharpe 0.46 でした。しかし次の結果になりました。
  * OOS 2015-2020/05: Sharpe **-0.64**、CAGR -7.8%、平均R -0.25。
  * FRED 2020-2026（FX部分）: Sharpe **-0.30**。
  * FRED 1976-2004 と 先物 1982-2004: どちらも Sharpe **≒0**。
* プラスだったのは先物OOS 2020/05-2024/03（指数と金の部分）の Sharpe 0.37 だけです。取引数45、t = 0.56 で、有意ではありません。
* ISの上位6候補（ユニバース・速度・損切りが違うもの）も、OOS Sharpe はすべてマイナス（-0.18〜-0.71）でした。選び方の問題ではなく、**この系統全体がOOSで機能していません**。
* DSR（IS、71試行）= **0.010**。
* ISの成績は2013年（アベノミクスの円安と株高、+37.3%）に集中しています。2013年を除くと IS Sharpe は 0.24 です。
* 指数と金を加えた効果（ISで確認）: ISでは FXのみの 0.30 から全体の 0.46 に上がりました。OOSでは次のとおりです。
  * 指数+金の部分: Sharpe 0.00。
  * FX部分: Sharpe -0.82。
  * 指数と金は負けを薄めるだけで、エッジは生みません。
* **FXトレンドの構造的な障害はスワップのマークアップ**です（年2.5%、売り買いとも）。
  * 3×ATRの損切りで1%リスクにすると、FXの建玉は1本で口座の約40%になります。平均エクスポージャーは口座の約2倍です。
  * その結果、マークアップだけで年4〜5%のコストになります。
  * スワップを除いた診断では FRED 1976-2004 の Sharpe は 0.44（50M: 0.59）でした。スワップ込みでは ≒0 です。1970〜90年代のFXトレンドの利益は、リテールのスワップ条件ではほぼ消えます。
  * OOS 2015-2020 はスワップ抜きでも Sharpe -0.32 でした。トレンド自体が負けた期間です。
* 50万円口座の最小ロットでは、3×ATR損切りの**金（0.01ロット = 1オンス）はISで一度も建ちません**。GBPJPY・GBPAUD なども頻繁に見送られます。

## 選ばれた設定と売買ルール（参考。採用は推奨しない）

`signal="ema", n=128 (fast=32), stop_atr=3.0, atr_n=20, trail_atr=0, entry_mode="state", short_risk=True, carry_min=-3.0, warmup=260`、ユニバース `all23`

* 銘柄（23）:
  * FX 15通貨ペア: USDJPY, EURUSD, GBPUSD, AUDUSD, USDCAD, EURJPY, GBPJPY, AUDJPY, CADJPY, EURGBP, EURAUD, GBPAUD, EURCAD, AUDCAD, GBPCAD
  * 金: XAUUSD
  * 株価指数CFD: US500, NAS100, US2000, JPN225, UK100, FRA40, AUS200
  * 日足はサーバー時間（NY17時締め）。
* 日足の確定（足 t）ごとに、終値の EMA(32) と EMA(128) を計算する（MT5 iMA、MODE_EMA、PRICE_CLOSE）。
  * `EMA32 > EMA128` なら状態 = 買い。`EMA32 < EMA128` なら状態 = 売り。
* **エントリー**: その銘柄がノーポジションで、履歴が260本以上あれば、状態の方向に次の足の始値で成行注文を出す。
  * ロールオーバー時間（サーバー 00時台）は避け、01:00 の足で約定する。
  * 状態が続いている間は毎日判定する。損切り後も、次の日足確定で状態が同じなら再エントリーする。
* **キャリーフィルター**: 前年の年平均政策金利（指数は配当利回り、金は0%）で、その方向の年間キャリーを計算する。
  * 買いのキャリー = 基軸 − 決済 − 2.5%。売りのキャリー = 決済 − 基軸 − 2.5%。
  * これが **-3%未満ならエントリーしない**（決済は制限しない）。
  * 当年の金利は使わない。
* **損切り**: 約定価格 ∓ 3 × ATR(20)（iATR、足 t の値）。固定で、トレーリングと利確はない。
* **決済・ドテン**: 保有と逆の状態になったら、次の足の始値で決済する。キャリーフィルターを通れば、同じタイミングで逆方向に建てる。
* **ロット**: 残高 × 1% ÷（損切り幅 × 1ロットの円価値）。ロット単位で切り捨て、最小ロット未満なら見送る。
* **口座全体の制約**: 1銘柄1ポジション、同時保有の初期リスク合計は8%まで、最大10ポジション（エンジン共通の条件）。
* ナンピン・グリッド・マーチンゲールはない。損切りは必ず建玉と同時に置く。

## 検証方法

* 探索は IS（2005-01〜2014-12、OANDA）だけで行った。71試行すべてをログに記録した。
* **ISスコア** = 2つの口座規模の IS Sharpe の平均。どちらも1%リスク。
  * 50万円（標準。FX 0.01ロット・指数 0.1ロットの最小単位が効く）。
  * 5,000万円（ロットの丸めなし）。
  * 取引数が150未満の設定は除外した。
* 段階:
  * **A（26試行）**: シグナルの種類と速度 × 損切り 3 / 5 ATR。ユニバースは事前に決めた `bal12`（FX 6 + 金 + 地域別の指数5）。
    * シグナル: EMA 16/64・32/128・64/256、TSMOM 63/126/252日、ドンチャン 50/100/200日（決済はその半分の期間）、EMAアンサンブル（32/64/128/256、4本中3本一致 or 全一致）、TSMOMアンサンブル（63/126/252、多数決 or 全一致）。
  * **B（15試行）**: Aの上位3種類について、損切り 2 / 4 / 7 ATR と、トレーリング 3 / 5 ATR。
  * **C（10試行）**: 上位2つについて、ATR期間100、指数・金は買いのみ、クロス時のみエントリー、キャリーフィルター -3%。改善した2つの組み合わせも試した。
  * **D（8試行）**: 上位2つについて、ユニバースを比較した。
    * `bal14`: 指数を7つ全部。
    * `all23`: 全銘柄。
    * `risk8`: 金と指数のみ。
    * `fx16`: 第1波のFX+金。
  * **E（12試行）**: 上位3候補の近傍（速度と損切りを ±25〜33%）でプラトー検定。「自分と近傍のISスコアの平均」が最大のものを機械的に選んだ。
* OOS・FRED・先物・コスト2倍は、選択後の1設定だけで評価した。近傍・部分ユニバース・他候補の数値も表示しているが、報告のためだけで選択には使っていない。
* 注意点が2つある。
  * プラトー検定では、近傍が取引数150未満（スコア -9）になった `bal12` と `bal14` が平均で大きく不利になった。
  * `bal14` 版（ISスコア 0.433、選択した設定は 0.437）も OOS Sharpe は -0.18 で、結論は変わらない（下の表）。
* **エンジンの不具合を回避している（共有コードは未修正）**:
  * 期間の終わりで保有中のポジションは、終了時刻（例: 2015-01-01）で決済扱いになる。ところがその日は日次エクイティの日付に含まれない。
  * そのため、最終日の値が「確定損益＋同じ建玉の含み損益」で**二重計上**される。この系統の IS では最終日だけで +20% 前後、例として EMA128・損切り5ATR の IS Sharpe が 0.37 に見えるが、正しくは 0.20。
  * 影響する期間: is、fred_pre、pst_pre、pst_oos（JPN225 の最終足が終了日と同じ日のため）。
  * スクリプトの `fix_equity` は、エンジン自身の `_daily_equity` で最終日を正しく再計算し、「最終エクイティ = 初期資金 + 損益合計」を assert で確認している。以下の数値はすべて修正後の値。

* 23銘柄を常時保有すると8%の上限に当たる。どの銘柄が枠を取るかは処理順で決まる（ISでは上限の方が結果が良かった）。それでも OOS がマイナスであることは変わらない。

## 主なリスク（仮に運用した場合）

1. **OOSの負け**: OOS と FRED 2020-2026 で平均Rがマイナス（t = -1.8 / -1.7）。IS の成績（DSR 0.01、2013年への集中）は偶然の範囲で説明できる。
2. **スワップのマークアップ**: エクスポージャー約2倍のFX保有は年約5%のコストになり、トレンドの総利益をほぼ相殺する。
3. **最小ロット**: 50万円では金が建たない。GBP系クロスも頻繁に見送られ、分散が名目より小さい。
4. **リスク上限と処理順の依存**: 常時保有型で銘柄数が枠（8本）を超えると、どの銘柄を持つかが偶然で決まる。
5. **長期保有**: 最長3年。エンジンはスワップをエントリー年の金利で計算しているため、金利が変わる局面ではコストがずれる。
6. **窓開け**: 固定損切りは週明けの窓で飛び越える（エンジンは始値で決済する）。

## エンジンへの報告事項

* `engine.run_portfolio` と `_daily_equity` で、期間終了時の強制決済が最終日のエクイティに二重計上される（上記）。
  * 対象: 終了日がデータの途中にある期間（is、fred_pre、pst_pre）と、最終足が終了日と同じ日の銘柄（pst_oos の JPN225）。
  * 影響: 終了時に保有中の建玉があると IS の CAGR と Sharpe が過大になる。他の系統の IS 数値も影響を受けている可能性がある。
  * 修正案: 強制決済の exit_time を「終了日より前の最後の日足」にする。または `_daily_equity` で最終日の含み損益から除外する。
* `instruments.policy_rate` は2005年未満を2005年として扱う。FRED プレ期間のスワップは当時の金利差を反映しない（既知の近似）。
