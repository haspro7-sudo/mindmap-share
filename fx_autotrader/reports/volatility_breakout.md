## 選定した設定（IS だけで選択）とルール

対象は全16銘柄です（IS の結果で銘柄を絞っていません）: USDJPY, EURUSD, GBPUSD, AUDUSD, USDCAD, EURJPY, GBPJPY, AUDJPY, CADJPY, EURGBP, EURAUD, GBPAUD, EURCAD, AUDCAD, GBPCAD, XAUUSD

時刻はすべて MT5 のサーバー時間です（NY+7h。H4 足は 00/04/08/12/16/20 時に始まる）。判定は確定した H4 足で行います。

1. **収縮の判定**（各 H4 足の確定時）: `ATR(6) / ATR(120) < 0.6`。
   * ATR は MT5 の `iATR(PERIOD_H4, n)`（shift=1、真の値幅の単純平均）です。
   * ATR(6) は直近24時間、ATR(120) は直近20営業日にあたります。
2. **収縮レンジ**: 直近6本の確定 H4 足（=24時間）の最高値 HH と最安値 LL。
3. **エントリー**: 同じ銘柄にポジションが無ければ、次の H4 足の始値で OCO の逆指値を2本置きます。
   * 買いの Buy Stop: `HH + 0.1×ATR(20)`
   * 売りの Sell Stop: `LL − 0.1×ATR(20)`
   * ATR(20) も H4 です。次の足が 00:00 に始まる場合は 01:00 に発注します（ロールオーバー回避）。
4. **注文の有効期間**: 注文は次の H4 確定まで有効です。
   * 次の足でも条件1が成立していれば、その時点の HH/LL で置き直します。
   * 条件1が崩れた場合は、最後に条件が成立した足から数えて **3本分**（その足の直後の3回の判定）まで、同じ価格で置き直します。
   * どちらかの価格に一度でも触れた後は、新しい収縮足が出るまで再発注しません。
   * 片方が約定したらもう片方は取り消します。
5. **損切り**（約定と同時に必ず設定）: 約定価格 ∓ D。`D = (HH − LL) + 0.2×ATR(20)`（下限 0.3×ATR(20)。実際には下限にかかることはありません）。
   * ちょうど逆指値の価格で約定した場合、損切りはレンジの反対側 − 0.1×ATR(20) になります。
6. **決済**: 利確指値もトレーリングもありません。約定後に6本目の H4 足が確定したら（約20〜24時間後）、次の H4 始値で成行決済します。
7. ナンピン・マーチン・グリッドはなし。1銘柄1ポジションです。
8. 資金管理（検証共通）: 1トレード＝残高の1%リスク、同時保有リスク合計8%まで、同時10ポジションまで、0.01ロット単位で切り捨て。

パラメータ（`fxlab/strategies/volatility_breakout.py` の `VolatilityBreakout`）:
`tf=H4, setup=atr_ratio, ar_thr=0.6, atr_s=6, atr_l=120, box_n=6, atr_n=20, buffer_atr=0.1, valid_bars=3, stop_mode=range, min_stop_atr=0.3, tp_r=0, trail_atr=0, max_hold=6, trend_n=0`

## 約定・コストの検証

* 判定は H4 で行います。逆指値の約定、損切り、時間決済は H1 足で処理し、同じ H1 足の中の順序（どちらの逆指値が先か、約定後に損切りに届いたか）は **M1 足** で判定します（共有エンジン標準）。
* 共有エンジンは、H1 足の中で M1 足が逆指値の価格を飛び越えて始まった場合でも、指値の価格で約定したことにします（楽観的）。
  * そこで M1 の始値で約定・損切りしたと仮定して再計算しました。影響は IS で +0.0014R（エントリー +0.0006R、損切り +0.0008R）と無視できる大きさでした。
* 逆指値のスリッページを3倍にしても IS の純R は +0.086R ですが、OOS は -0.030R です。コストを2倍にすると OOS は -0.065R（t=-2.34）となり、明確にマイナスです。

## エンジンの問題（共有コードへの指摘。修正はしていません）

1. `engine._kernel`: H1 足の中で逆指値が約定したとき、約定価格は `max(H1始値, 注文価格)` です。M1 足がすでに注文価格を飛び越えて始まっていても、注文価格で約定したことになります。H1 の途中での損切りも同様です（窓を考慮するのは H1 始値だけ）。この戦略への影響は +0.0014R と軽微です。ただし指標発表直後の急変でブレイクする戦略では、楽観的な偏りになり得ます。
2. `engine._kernel` と `mt5/TitanStagedEA.mq5` のずれ:
   * エンジンは約定価格から損切り幅と利確幅を測ります。EA は逆指値を置いた時点で、SL/TP を注文価格から固定しています。
   * このため窓開けで飛び越えて約定した場合（本戦略では2.1%）、EA の損切りはエンジンより遠く、利確は近くなります。
   * また、エンジンはミッド価格で約定を判定しますが、EA の Buy Stop は Ask で約定します。
3. `backtest.m1_server_bars` の `lru_cache(maxsize=4)`: 16銘柄で `evaluate()` するたびに M1 を全部読み直します（約40秒/回）。正しさの問題ではありませんが、探索が遅くなります。

## 1億円目標への含意

* この戦略群（NR4/NR7、インサイドバー、ボリンジャー幅スクイーズ、ATR比の収縮ブレイク）には、コストを上回る優位性は確認できませんでした。

  * リスクを上げて複利で増やす（段階的に増資する）前提そのものが成り立ちません。
* OOS の最大DDは 44.5% です（1%リスク）。リスクを2%に上げれば、資金の大半を失う水準です。
