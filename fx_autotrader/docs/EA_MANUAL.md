# TitanPortfolioEA 運用マニュアル

`mt5/TitanPortfolioEA.mq5`（MetaTrader 5 用）の導入・検証・日常運用の手順です。

## 1. 準備

| 項目 | 推奨 |
|---|---|
| 口座 | Titan FX **ゼロ・ブレード口座、MT5、円建て**（ヘッジング口座。ネッティング口座では EA が起動しない） |
| 最初の口座 | **デモ口座**（サーバー `TitanFX-MT5-Demo`）。本番（`TitanFX-MT5-01`）はデモの合格条件を満たしてから |
| 動かす場所 | 24時間動く Windows VPS（Titan FX の VPS はニューヨーク）。**Windows の時計を NTP で同期**する（gotobi は 09:55:00 ちょうどが大事なため） |
| 通知 | MT5 のスマホアプリの MetaQuotes ID を、PC の MT5「ツール → オプション → 通知」に登録する。停止や決済失敗がスマホに届く |

## 2. インストール

1. MT5 を開き、「ファイル → データフォルダを開く」から `MQL5/Experts/` に `TitanPortfolioEA.mq5` をコピーする。
2. MetaEditor でファイルを開き、**コンパイル（F7）** する。エラー0件を確認する。
   * この環境ではコンパイラを実行できないため、MQL5 の文法・API は独立したコードレビュー2回（計39件の指摘を修正）で確認しています。万一エラーが出たら、その行とメッセージを知らせてください。
3. MT5 で **USDJPY の M1 チャートを1枚だけ** 開き、EA をドラッグする（どのチャートでも動くが、1つの端末に1枚だけ）。
4. 「アルゴ取引」ボタンを ON にする。EA のプロパティで「アルゴ取引を許可」にチェックを入れる。
5. 「エキスパート」タブに `INIT` 行が出ることを確認する。例：`v1.21 login=… rule=GMT+3 live=GMT+3 jst=… gotobi_today=…`。
   * `rule` と `live` が違う日は gotobi を見送ります（`CLOCK` 行）。

## 3. 主な入力（初期値＝Stage 1）

| 入力 | 初期値 | 意味 |
|---|---|---|
| InpSymbolSuffix | "" | 銘柄名に接尾辞がある口座（マイクロ口座の `-m` など）で指定 |
| InpMagicBase | 26092600 | マジック番号の基準（+1 gotobi、+2 逆張り、+3 キャリー） |
| InpServerDST | 0 | テスターでの時計ルール（0 = 米国式、NY+7時間）。本番は実際の時計と照合される |
| InpGotobiOn / InpGotobiRiskPct | true / **0.5** | gotobi の ON/OFF と 1回のリスク（残高の%） |
| InpMeanRevOn | false | 逆張り（**デモ専用**） |
| InpCarryOn | false | キャリー（条件を満たすペアが出て、残高100万円以上になってから） |
| InpThrottleDDPct / InpThrottleMult | 4.0 / 0.5 | 残高がピークから4%下がったらリスク半減（リスクの8倍） |
| InpHaltDDPct | 6.0 | 評価額がピークから6%下がったら全決済して停止（リスクの12倍） |
| InpDailyLossPct | 3.0 | 1日の損失が3%に達したら、その日は新規エントリーしない |
| InpGotobiMaxSpread | 0.7 | gotobi は発注時のスプレッドが 0.7pips 以下のときだけ発注 |
| InpGotobiWindowSec | 60 | エントリーできるのは 09:55:00〜09:56:00 JST のみ。約定しなければその日は見送り |

**リスクを上げるとき**は、次の3つを同じ比率で変えてください。
* InpGotobiRiskPct（例：1.0）
* InpThrottleDDPct（リスクの8倍 → 8.0）
* InpHaltDDPct（リスクの12倍 → 12.0）

## 4. Stage 0：検証（本番の前に必ず）

### 4-1. 2020〜2026年の検証（研究では分足データがなかった期間）

1. MT5「表示 → ストラテジーテスター」を開き、次のように設定する。
   * エキスパート：TitanPortfolioEA
   * 銘柄：USDJPY、時間足：M1
   * モデル：**「リアルティックに基づいた全ティック」**
   * 期間：**2020.06.01〜2026.09.24**
   * 初期証拠金：500000 JPY、レバレッジ 1:500
   * 入力：InpServerDST=0（2026年10月末の観察結果で 1 に変える場合あり）
2. 実行後、テスターのエージェントフォルダ（`Tester/Agent-…/MQL5/Files/TitanPortfolioEA_26092600_tester.csv`）をコピーし、次を実行する。
   ```bash
   python scripts/monitor_ea_log.py TitanPortfolioEA_26092600_tester.csv
   ```
3. 判定
   * **`[P5]` の 09:55→10:05 の平均値動きが +1.0pip 未満**、または**テスターの純損益がマイナス**なら、gotobi は不採用です。
   * その場合、このシステムは本番で使わない、が結論になります。

### 4-2. バックテストとの一致確認（2018〜2020年）

1. 同じ設定で、期間を **2018.01.01〜2020.05.15** にしてテストする。
2. 次を実行する。
   ```bash
   python scripts/monitor_ea_log.py TitanPortfolioEA_26092600_tester.csv --compare
   ```
3. 合格基準
   * gotobi のエントリー日が `reports/expected_trades.csv`（166件）と一致すること。祝日カレンダーは決まった計算なので、日付は100%一致するはず。
   * エントリー価格は95%以上が1pip以内。

   研究データ（OANDA）と Titan FX の価格は少し違うので、価格の完全一致は求めません。

### 4-3. デモ口座で3か月以上（gotobi 30回以上）

* 期間に **2026/10/30** を必ず含めてください。
  * この週（10/26〜30）は米国と欧州のサマータイムがずれています。
  * `INIT` 行や `CLOCK` 行の `live=GMT+?` を確認してください。
  * GMT+3 なら米国式（InpServerDST=0 のまま）、GMT+2 なら欧州式（InpServerDST=1 に変更）です。
* 合格条件は `docs/STAGED_PLAN.md` の Stage 0 のとおりです。
  * 約定時刻が 09:55:03 以内
  * 不利約定の平均が 0.7pip 以下
  * 往復コストが 2.0pips 以下 など
* 確認は `python scripts/monitor_ea_log.py <デモのログ>` で行えます。

## 5. 本番運用（Stage 1 以降）

* **毎週**
  * `python scripts/monitor_ea_log.py <ログ>` で、値動き指標（P5）、執行品質（P6）、累積R（P3/P4）を確認する。
  * `PAUSE` や `DROP` が出たら、`docs/STAGED_PLAN.md` の停止ルールに従う。
* **停止（HALT）したとき**
  1. スマホに通知が届き、EA はすべて決済して止まります。
  2. 原因を確認し、デモに戻して見直してください。
  3. 再開するときは、MT5 の「ツール → グローバル変数（F3）」で `TPEA_<口座番号>_26092600_halt` を削除する。評価額のピークは停止時点に戻してあるので、すぐには再停止しません。
* **入出金**
  * いつでも構いません。EA は取引履歴から入出金を検出し、ドローダウン判定を自動で補正します（税金の出金で誤停止しません）。
* **毎年2月**
  * 内閣府が翌年の春分・秋分の日を発表したら、`python -m pytest tests/test_calendar.py` に翌年分を追加して確認する。
  * 臨時の祝日ができたら、`InpJpExtraHolidays` に `YYYY.MM.DD` を追加する。
* **毎年1月（キャリーを使う場合のみ）**
  * `InpRates` に前年の年平均金利の行を追加する（小数2桁、確定した年のみ）。
* **してはいけないこと**
  * 同じ口座の EA を、2つのチャートや2つの端末（自宅PCとVPSなど）で同時に動かさない。
    * 同じ端末内ではロックで防いでいますが、別の端末同士は防げません。
  * 口座の途中で InpMagicBase を変えない。

## 6. ログの見方（CSV：時刻, 種類, 銘柄, 内容）

| 種類 | 内容 |
|---|---|
| INIT | 起動。時計（rule/live）、当日が gotobi か、残高 |
| OPEN / ERR_OPEN | 発注。bid/ask、SL、リスク額、結果コード、約定価格 |
| CLOSE / ERR_CLOSE | EA による決済と、その失敗（失敗はスマホにも通知） |
| EXIT | ポジション決済（損切りを含む）の純損益 |
| GTB_MECH | 五十日の 09:55→10:05 の仲値の動き（取引の有無にかかわらず毎回） |
| SKIP | 見送り（スプレッド、日次損失上限、最小ロット未満など） |
| CASHFLOW | 入出金を検出し、ピークを補正した |
| CLOCK | 時計の不一致で gotobi を見送った |
| NOTIFY / HALT | 停止など重要なお知らせ |

## 7. よくある問題

* **起動しない（INIT_FAILED）**
  * 同じマジック番号の EA が別チャートで動いていないか確認する。
  * クラッシュ後の古いロックが残っている場合は、グローバル変数 `TPEA_26092600_lock` を削除する。
* **起動直後に消える**
  * ネッティング口座です。ヘッジング口座で使ってください。
* **gotobi が約定しない**
  * `SKIP ... spread` が出ている場合は、スプレッドが 0.7pips を超えています。そのまま見送るのが正しい動作です。
  * 頻発する場合は、口座タイプ（ブレード）と VPS の場所を確認してください。
* **銘柄が見つからない**
  * InpSymbolSuffix を口座の銘柄名に合わせる（例：`-m`）。
