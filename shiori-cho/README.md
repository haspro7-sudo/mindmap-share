# しおり帳（Shiori Companion）

**作品に「しおり」を一枚はさむだけ。** 同人ゲームや音声作品に後から追加（アド）できる、スマホ向けのコンパニオンWebアプリ（PWA）です。

- **プレイヤー**は、買った作品の進み具合を記録できます。ネタバレしない段階ヒントで最後まで遊び切り、作中の「合言葉」を入れると封印された「おまけ」（キャラクターからの手紙、あとがき、後日談など）が手元のスマホで開きます。
- **サークル（作者）**は、アプリ内の「サークル工房」で `shiori.json` を1つ作って作品のzipに同梱し、作中に合言葉（またはQR）を表示するだけで、プラグインなしで「クリア特典」を追加できます。
- サーバーもアカウントも使いません。記録はすべて端末の中だけに保存されます。人前でも使いやすいように、おしのびモード・隠すボタン・画面ロックを備えています。

> しおり帳はDLsite及び各サークルとは関係のない非公式ツールです。DLsiteのサイトに接続したり、情報を取得したりすることはありません。作品ファイルやDRMにも一切触れません。

## なぜ体験価値が上がるのか

| 課題 | しおり帳での解決 |
|---|---|
| 間があくと「どこまで進めたか・次に何をするか」を忘れる | **前回の続き**：プレイ記録を終えるときの一行メモ（どこまで／次にやること）と現在地を、次に開いたときに一番上に表示（「3日ぶり」など） |
| 攻略情報を探すとネタバレや不適切な画像に当たる | **段階ヒント**：作者のヒントを「示唆 → 方向 → 答え」の順に長押しで1段ずつ開く。答えの段は確認付き。ノーヒントで達成した項目にはバッジ |
| 取り返しのつかない要素を取り逃す | **取り返し注意**：現在地の手前で「この先に進む前に確認を」とだけ警告（何があるかは言わない） |
| クリア後の余韻が作品の外に残らない | **封印おまけ**：エンディングで表示される合言葉を入れると、手紙やあとがきが封筒を開ける演出つきで届く。全エンディングで開く「あとがき」なども作れる |
| 家族や人前で見られたくない | **おしのびモード**：一覧は別名（「作品A」など）だけ表示、「隠す」ボタン／Escキーで無地の「メモ」画面に即切り替え、タスク切り替え画面に中身を出さない、PINロック |
| 作者がいない作品では使えないのでは？ | **かんたんしおり**：エンディング数・CG数・トラック数などを入れるだけで、その場でチェックリストを作成 |

サークル側にとっては「攻略ありますか？」への答え（公式の段階ヒント）になります。「クリア特典：あとがき収録（しおり帳対応）」のように作品の差別化にも使えます。既存作品にも、アップデートでファイルを1つ足すだけで対応できます。

## 主な機能（v1）

- 年齢確認（自己申告）、オンボーディング（おしのびモード・PIN・自動ロック）
- 本棚：状態（積み／プレイ中／クリア／コンプ／保留）、並び替え、進捗バー、続きからカード、バックアップのお知らせ
- 作品ページ：進捗（グループ別・全体）、いまどこ？、取り返し注意、段階ヒント、NEW／ノーヒントバッジ、おまけ、プレイ記録、メモ（`||ネタバレ||` 記法）
- 合言葉：英数字9文字（例 `ST4-RMA-P1X`、チェック文字で入力ミスを即検出）または ひらがな5語（例 `ほたる・かえで・つばめ・こだま・すずめ`、音声作品向け）
- QR／URLでの解放：`#/u/<作品ID>/<合言葉>`。まだしおりを読み込んでいない合言葉は「保留」として取っておき、読み込んだ時点で自動解放
- バックアップ：JSONで書き出し／読み込み（置き換え・まとめる）、パスフレーズ暗号化も可能
- サークル工房：作品情報・章・目標・ヒント・おまけの編集、合言葉の自動生成、点検（検証・自己テスト・ネタバレ漏れ検査）、プレイヤー画面でのプレビュー、配布キット（zip）の書き出し
- サンプル作品2本（架空・全年齢）と、PC画面シミュレータ（`#/demo-pc`）
- PWA：インストール可能、初回表示のあとはオフラインで動作

## 使ってみる（サンプル）

1. アプリを開き、本棚の「サンプルを試す」を押します。
2. 設定 → ヘルプ →「サンプルの合言葉」、または `#/demo-pc`（PC画面シミュレータ）でエンディングまで進み、表示された合言葉を「合言葉」タブに入れます。
   - 星読みの図書館（サンプルA）：`ST4-RMA-P1X` / `M00-NDE-SKR` / `NEK-0T0-M0E` / `SK1-ES0-NGM`
   - 雨音と読書の時間（サンプルB）：`ほたる・かえで・つばめ・こだま・すずめ` / `AMA-0T0-N1J`
3. 1つ目で「司書ミナからの手紙」が、4つそろうと「あとがき」が開きます。

## サークル向け：作品にしおりを追加する

1. 設定 → サークル向け →「サークル工房」で新規作成します。作品情報・章・目標（エンディングや実績）・ヒント・おまけを入力します。
2. 合言葉が必要な目標には、合言葉が自動で作られます（英数字 または ひらがな5語）。
3. 「点検」で検証します。検証・全合言葉の自己テスト・ネタバレ漏れ検査がすべて通ると、「書き出し」でキットをダウンロードできます。
   ```
   同梱用_PUBLIC/shiori.json          ← 作品のzipに同梱（公開してOK）
   同梱用_PUBLIC/はじめに.txt
   非公開_ゲームに埋め込む/codes.csv   ← 合言葉一覧（同梱しない）
   非公開_ゲームに埋め込む/qr/*.png    ← 合言葉のQR画像
   非公開_ゲームに埋め込む/エンジン別の表示例.txt
   非公開_控え/project.shiori-studio.json
   告知文テンプレート.txt
   README_最初に読んでください.txt
   ```
4. 作中の該当場面（エンディングなど）で合言葉を表示します。表示のしかたはエンジンを問いません。
   - RPGツクールMV/MZ：`しおり帳の合言葉：\C[3]ST4-RMA-P1X\C[0]`
   - ティラノ：`しおり帳の合言葉：ST4-RMA-P1X[p]`
   - 音声作品：最後のトラックで読み上げる／台本の最後のページに記載

作品ページや作中にURL・QRを載せる場合は、DLsiteの作品登録ルールを必ず確認してください。合言葉の文字列だけでも使えます。

### 合言葉のしくみ（ネタバレ防止であってDRMではありません）

`shiori.json` には、合言葉そのものも、エンディング名やおまけの本文も平文では入っていません。

- 合言葉 → PBKDF2-HMAC-SHA256（作品ごとのソルト、既定20万回）で鍵を作り、HMACの照合タグ（16バイト）だけを保存します。
- 目標の本当の名前とおまけ本文は、合言葉から導いた鍵で AES-GCM により封印します。
- 「すべて（allOf）」条件は、必要な合言葉の鍵をすべて連結して初めて復号できます。暗号として強制されるので、アプリの表示だけのチェックではありません。

ファイルを開いてもネタバレしないことが目的です。本編の有料コンテンツをおまけに入れないでください。ヒントと公開ラベルは誰でも読めます。

## プライバシー

- 通信なし：解析・広告・外部フォント・CDN を使いません。ビルド時に CSP（`connect-src 'self'`）を埋め込み、`npm run check:dist` で外部ホストが混入していないことを検査します。
- 保存先：ブラウザの IndexedDB（プレイヤー用 `shiori`、工房用 `shiori-studio`）のみ。
- PINは画面ロックです。保存データ自体は暗号化されません（パスフレーズ付きバックアップは暗号化されます）。
- iPhone では Safari とホーム画面のアプリで保存領域が別になります。バックアップの利用をおすすめします。

## 開発

```bash
cd shiori-cho
npm ci
npm run dev          # 開発サーバー
npm test             # vitest（コア・ストレージ・サービス・UI）
npm run typecheck    # tsc -b（strict）
npm run lint         # oxlint（react/no-danger など）
npm run build        # 本番ビルド（PWA + CSP）
npm run check:dist   # dist に外部ホストや生HTML APIが無いか検査
npm run demo:build   # サンプル作品の shiori.json を再生成
```

- 技術：Vite + React 19 + TypeScript（strict）、zod 4、idb、fflate、qrcode-generator、vite-plugin-pwa
- 構成：
  - `src/core/`：純粋ロジック。React・DOM・通信なしで、`boundary.test.ts` で強制
  - `src/storage/`：IndexedDB／メモリ実装と、共通の契約テスト
  - `src/app/`：サービス層
  - `src/ui/`：画面
  - `src/demo/`：サンプル作品
- 仕様：[`docs/SPEC.md`](docs/SPEC.md)
- GitHub Pages：Actions の `shiori-cho` ワークフローを手動実行（deploy にチェック）すると公開されます。相対パスとハッシュルーティングなので、サブパスでも動きます。
